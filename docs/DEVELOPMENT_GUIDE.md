# Development guide

How a feature is put together in TriviaMore, from the server function to the form that calls it. `CLAUDE.md`
holds the layering rules, the commands, the database rules and the verification steps; this guide shows the
patterns with code from the repo and does not repeat those rules. The security model is in `SECURITY.md`, the
UI rules in the `design-system` skill and `DESIGN_SYSTEM.md`.

## Stack

| Layer | Tool |
|---|---|
| Framework | TanStack Start (React 19, Vite, Nitro), file-based routes in `src/routes/` |
| Server state | TanStack Query v5 |
| Database | Postgres through Drizzle on `pg` (`src/db/`) |
| Auth | Better Auth inside the app (`src/lib/auth/server.ts`) |
| Files | Garage, an S3 store, through `src/lib/storage/server.ts` |
| Validation | zod, shared by forms and server inputs |
| Forms | React Hook Form with `standardSchemaResolver` |
| Tables | the one `DataTable` in `src/components/data-table/` (TanStack Table v9) |
| Logging | Seq, through `log` from `@/lib/logging/server` |
| Secrets | Infisical, injected by the `pnpm` scripts |

The app no longer uses Supabase.

## Where the code goes

One folder per domain in `src/lib/` (`quiz`, `requests`, `user`, `admin`, `notifications`, `catalog`, …),
split into `api/`, `service.ts` (or `service/<area>.ts`), `db/` when a query is shared, `schemas.ts`,
`types.ts`, `queries.ts` and `mutations.ts`. `CLAUDE.md` says what goes in each and why; the
`stack-web-ts:server-functions` skill has the reasoning and the rules for changing an endpoint that open tabs
still call.

Client code imports from `api/` (through `api/index.ts`), `queries.ts`, `mutations.ts`, `schemas.ts` and
`types.ts`, never from `service` or `db/`. A service may call another domain's service or `db/` function on the
server: `createRequest` calls `notifyAdminsInScope` from `notifications`.

Components live in `src/components/<feature>/`, primitives in `src/components/ui/`, hooks in `src/hooks/`.

## Server functions

An endpoint declares its method, its middleware and its input, and hands off to the service:

```ts
// src/lib/user/api/toggle-bookmark.ts
import { createServerFn } from "@tanstack/react-start";

import { authMiddleware } from "@/lib/server/middleware/auth";

import { questionIdSchema } from "../schemas";
import { toggleBookmark } from "../service/bookmarks";

export const toggleBookmarkFn = createServerFn({ method: "POST" })
	.middleware([authMiddleware])
	.inputValidator(questionIdSchema)
	.handler(({ data, context }) => toggleBookmark(context.user.id, data.questionId));
```

A public read that changes with the user takes `optionalAuthMiddleware`, and `context.user` may be `null`:

```ts
// src/lib/quiz/api/get-quiz.ts
export const getQuizFn = createServerFn({ method: "GET" })
	.middleware([optionalAuthMiddleware])
	.inputValidator(quizIdSchema)
	.handler(({ data, context }) => getQuiz(context.user?.id ?? null, data.quizId));
```

The admin endpoints declare no middleware; the service calls the guard that fits what is touched:

```ts
// src/lib/admin/service/questions.ts
export async function updateQuestion(id: string, updates: UpdateQuestionInput) {
	await requireContentManagerForQuestion(id);
	// ...
}
```

Rules:

1. `GET` for reads, `POST` for writes. A `GET` server function never writes.
2. Every endpoint has middleware or a guard in its service; which one is in `SECURITY.md`.
3. The user id comes from `context.user.id` or the guard's return value, never from `data`.
4. Every input goes through `.inputValidator()` with a zod schema.
5. Return `null` rather than `undefined`; TanStack Query rejects `undefined` from a `queryFn`.
6. A server function is not called from another server function's handler: that is an HTTP round trip to
   ourselves. Call the service or the guard directly, which is why the guards are plain functions.
7. Ids are generated by Postgres (`uuid().defaultRandom()`); read them back with `.returning()`.
8. A change to a server function runs `pnpm smoke:reads` and `pnpm smoke:writes`, and a new read path goes into
   `scripts/smoke/read-endpoints.ts` unless `requireAdmin()` guards it.

## Services and queries

A service owns the flow: authorization, its own queries, transactions and the mapping to view models. It uses
`getDb()` from `@/db`. Several writes that must land together share a transaction, and anything called inside
it takes the `tx`:

```ts
// src/lib/requests/service/user-requests.ts
return getDb().transaction(async tx => {
	const [request] = await tx
		.insert(contentRequests)
		.values({ userId, requestType: REQUEST_TYPE[input.type], submittedContent: submitted /* … */ })
		.returning({ id: contentRequests.id });

	await notifyAdminsInScope(tx, { id: request.id, title: generateTitle(submitted) /* … */ });

	return { id: request.id };
});
```

A function in `db/<table>.ts` takes `db: DbOrTx` first, so it runs standalone or inside a transaction, and has
no authorization of its own:

```ts
// src/lib/catalog/db/sections.ts
export async function findSectionById(db: DbOrTx, sectionId: string) {
	const [section] = await db
		.select()
		.from(sections)
		.where(eq(sections.id, sectionId))
		.limit(1);
	return section;
}
```

RLS filters nothing for the app, so a read that belongs to one user says so in its `where`
(`eq(bookmarks.userId, userId)`), and a read of question content goes through `src/lib/auth/checks.ts`.

Schema, migration and row-type work follows the `stack-web-ts:drizzle-schema` skill and the database rules in
`CLAUDE.md`.

## Errors

Throw an `AppError` subclass from `src/lib/server/errors.ts` for anything the user should read. The message
is Italian and specific:

```ts
import { Conflict, Forbidden, Invalid, NotFound, Unavailable } from "@/lib/server/errors";

if (!question) throw new NotFound("Domanda non trovata");
if (!scope.isPublic) throw new Forbidden("Non puoi gestire sezioni private.");
```

| Class | Use for |
|---|---|
| `Unauthorized` | no session (thrown by `authMiddleware`) |
| `Forbidden` | signed in, not allowed |
| `NotFound` | the row does not exist |
| `Conflict` | a state that forbids the action; `rethrowUniqueViolation(error, message)` maps a unique-key violation to one |
| `Invalid` | input that passed the schema but fails a rule |
| `Unavailable` | a dependency failed (S3, mail); log the cause first |

Any other error is logged once by `errorMiddleware` and replaced by a generic message with a reference, so do
not catch-log-rethrow and do not put detail in a plain `Error`. Guards throw `redirect()`; let it through.

On the client, `useMutationWithToast` shows `error.message` in a toast; a `useSuspenseQuery` error reaches the
route's error boundary. Components do not wrap these in `try/catch`.

## Queries

Each domain exports a query factory from `queries.ts`. Keys are `["domain", "entity", ...params]`, and
`staleTime` comes from `STALE_TIME` in `src/lib/shared/cache.ts` (`FAST` 30 s, `STANDARD` 5 min, `SLOW`
10 min; the router default is 5 min):

```ts
// src/lib/user/queries.ts
bookmarks: () =>
	queryOptions({
		queryKey: ["user", "bookmarks"],
		queryFn: () => getUserBookmarksFn(),
		staleTime: STALE_TIME.STANDARD,
	}),
```

A route loads what the page needs, and the component reads it with `useSuspenseQuery`:

```tsx
// src/routes/_app/user/bookmarks.tsx
export const Route = createFileRoute("/_app/user/bookmarks")({
	loader: ({ context }) => context.queryClient.ensureQueryData(userQueries.bookmarks()),
	head: () => seoHead({ title: "Segnalibri", noindex: true }),
	pendingComponent: BookmarksSkeleton,
	component: BookmarksPage,
});

function BookmarksPage() {
	const { data: bookmarks } = useSuspenseQuery(userQueries.bookmarks());
	// ...
}
```

A route with a `pendingComponent` has a skeleton in `src/components/skeletons/`; change both together. Use
`useQuery` only for data loaded on demand. `refetchInterval` is for the notification and changelog counts
(60 s) and little else.

## Mutations

Components call mutation hooks from `mutations.ts`, never server functions. Most hooks wrap
`useMutationWithToast` from `src/hooks/useMutationWithToast.ts`, which invalidates the listed keys and shows the
toast:

```ts
// src/lib/requests/mutations.ts
export function useCreateRequest(onSuccess?: () => void) {
	return useMutationWithToast(createRequestFn, {
		successMessage: "Proposta inviata con successo",
		invalidateKeys: [
			["requests", "mine"],
			["admin", "requests"],
			["admin", "requestCount"],
			["notifications"],
			["notifications", "unreadCount"],
		],
		onSuccess,
	});
}
```

Invalidate every view the write changes, the other role's views included. `onSuccess` is for UI side effects
such as closing a dialog. The `undo` option turns the toast into an undoable one. A mutation whose input is
not `{ data }`, or which needs work before the call, uses `useMutation` directly, as `useToggleBookmark` and
`useUploadAvatar` do.

## Uploads

Bytes go to the server as `FormData` with a `file` field; the server function's schema is
`formFileSchema(maxBytes, message)` from `src/lib/storage/schemas.ts`, and the service checks the bytes and
picks the key before calling `putObject`. The client side, from `src/lib/avatar/mutations.ts`:

```ts
const form = new FormData();
form.append("file", await resizeForAvatar(file), "avatar.webp");
return uploadAvatarFn({ data: form });
```

Client-side type and size checks are for a quicker message only. Private files are read back through a route,
as `src/routes/api/requests/$requestId/attachment.ts` does; see `SECURITY.md`.

## Schemas

zod schemas live in the domain's `schemas.ts` and serve both the form and `.inputValidator()`:

```ts
z.string()
	.min(2, "Il nome deve essere di almeno 2 caratteri")
	.max(50, "Il nome non può superare i 50 caratteri")
	.trim();
```

- Every string has a maximum length and is trimmed; every message is Italian.
- Ids are `z.string().uuid()` (or `z.uuid()`), enumerations `z.enum([...])`.
- Cross-field rules use `.refine` or `.superRefine` (`questionMcRefinement` in `src/lib/shared/question-schema.ts`).
- Polymorphic input is a discriminated union on `type`.
- Export the input type: `export type LoginInput = z.infer<typeof loginSchema>`.

## Types

Row types come from the Drizzle schema in the domain's `types.ts`:

```ts
// src/lib/requests/types.ts
import type { contentRequests } from "@/db/schema";

export type ContentRequest = Omit<typeof contentRequests.$inferSelect, "submittedContent">;
export type ContentRequestStatus = ContentRequest["status"];
```

A jsonb column gets its own discriminated union (`SubmittedContent`), and stored jsonb is parsed before use
(`parseSubmittedContent`), not cast. No `any`: use `unknown` and narrow. Prefer `type` over `interface`, and
`import type` for type-only imports.

## Forms

React Hook Form with the domain schema and the `Form` primitives from `src/components/ui/form.tsx`:

```tsx
// src/components/auth/login-form.tsx
const form = useForm<LoginInput>({
	resolver: standardSchemaResolver(loginSchema),
	defaultValues: { email: "", password: "" },
});

return (
	<Form {...form}>
		<form onSubmit={form.handleSubmit(onSubmit)} className="grid gap-5">
			<FormField
				control={form.control}
				name="email"
				render={({ field }) => (
					<FormItem>
						<FormLabel>Email</FormLabel>
						<FormControl>
							<Input type="email" autoComplete="email" {...field} />
						</FormControl>
						<FormMessage />
					</FormItem>
				)}
			/>
		</form>
	</Form>
);
```

Disable the submit button while the mutation `isPending`.

## Components

- Every dialog has a `DialogDescription`; Radix warns without one.
- Animations respect `useReducedMotion` (`src/hooks/useReducedMotion.ts`).
- `cn()` for conditional classes, never string concatenation.
- `e.stopPropagation()` on a button inside a clickable row or card.
- Every table is the `DataTable`; use the `stack-web-ts:data-tables` skill.
- Every `ui/` primitive and shared component has a story; use the `storybook` skill.
- Colours, radii, shadows and motion follow the `design-system` skill.

## Naming

| Thing | Style | Example |
|---|---|---|
| Files | kebab-case | `request-form.tsx`, `toggle-bookmark.ts` |
| Components, types | PascalCase | `QuestionCard`, `SubmittedContent` |
| Functions | camelCase, verb first | `getUserBookmarks`, `toggleBookmark` |
| Server functions | camelCase + `Fn`, file named after it | `startQuizFn` in `api/start-quiz.ts` |
| Hooks | `use` prefix | `useCreateRequest` |
| Query factories | `<domain>Queries` | `requestQueries` |
| Constants | SCREAMING_SNAKE_CASE | `STALE_TIME`, `MAX_SESSION_ITEMS` |

Code and comments are in English; UI copy is in Italian. Comments follow the rules in `CLAUDE.md`.

## Before calling a feature done

- [ ] `pnpm exec tsc --noEmit`, `pnpm test` and `pnpm build:dev` pass; a UI change also passes
      `pnpm build-storybook`.
- [ ] A server-function change passes `pnpm smoke:reads` and `pnpm smoke:writes`.
- [ ] The `SECURITY.md` checklist holds.
- [ ] Mutations invalidate every view they change.
- [ ] User-facing text is Italian and errors are specific `AppError`s.
- [ ] A changed page with a `pendingComponent` has its skeleton updated.
- [ ] The UI works in light and dark themes and on a narrow screen (checked in the browser by the user).
